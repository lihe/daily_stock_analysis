# GitHub Action 第二阶段提速设计

## 目标

在保持定时任务、行情降级链路和分析结果口径兼容的前提下，减少手动测试等待与单股内部重复行情请求：

1. 手动 `workflow_dispatch` 不执行随机延迟，定时 `schedule` 继续保留 0～59 秒随机延迟。
2. A 股单次分析中，基本面估值复用主流程已成功取得的实时行情，不再重复请求腾讯接口。

## 已确认现状

- `.github/workflows/00-daily-analysis.yml` 的随机延迟步骤没有触发条件，因此手动和定时任务都会执行。
- `StockAnalysisPipeline.analyze_stock()` 先调用一次 `get_realtime_quote()`，随后 `DataFetcherManager.get_fundamental_context()` 的估值阶段再次调用同一入口。
- Action `31008604683` 中，`600797`、`002315` 均出现两次腾讯实时行情请求；第二次分别耗时约 6.88 秒和 6.01 秒。
- 首次实时行情失败时，用户要求保留基本面阶段重试，避免缓存失败结果导致可恢复故障被固化。

## 方案选择

采用请求级显式复用：主流程把已取得的行情对象以可选参数传给基本面聚合。

不采用以下方案：

- Manager 级 TTL 缓存：会引入跨股票分析、跨任务运行的过期与线程安全语义。
- 完整 AnalysisContext 重构：改动范围超过本阶段目标。

## 详细设计

### 手动触发跳过随机延迟

为随机延迟步骤增加事件条件：

```yaml
if: github.event_name == 'schedule'
```

行为矩阵：

| 触发事件 | 随机延迟 | 其他步骤 |
| --- | --- | --- |
| `schedule` | 执行 | 保持不变 |
| `workflow_dispatch` | 跳过 | 保持不变 |

该条件与 `force_run` 无关；`force_run` 仍只控制交易日检查。

### 单股内部复用实时行情

`DataFetcherManager.get_fundamental_context()` 增加仅供关键字传递的可选 `realtime_quote` 参数。

A 股估值阶段遵循以下顺序：

1. 参数为成功行情对象时，直接从该对象读取 `pe_ratio`、`pb_ratio`、`total_mv`、`circ_mv`，记录复用日志，不再次访问实时行情数据源。
2. 参数为 `None` 时，继续执行现有 `get_realtime_quote()`、超时、重试和 fallback 逻辑。
3. 行情对象字段不完整时维持当前 `partial` 状态，不额外发起补齐请求；主流程的首次实时行情入口已经执行现有多源补充逻辑。

`StockAnalysisPipeline.analyze_stock()` 使用关键字参数传入已取得的 `realtime_quote`。其他调用方不传该参数时，行为完全不变。复用范围限定在单只股票的一次分析调用内，不新增全局缓存、TTL 或配置项。

## 异常与兼容性

- 首次实时行情成功：基本面估值复用，不产生第二次网络请求。
- 首次实时行情返回空或抛出异常：基本面阶段按原逻辑重新尝试。
- 基本面功能关闭：保持现有 `not_supported` 返回，不使用传入行情。
- 非 A 股：本阶段保持现有路径，不扩大行情复用范围。
- 腾讯或其他数据源 fallback 顺序、实时行情对象结构、报告字段均不改变。

## 测试设计

按 TDD 先添加并验证失败测试，再实现最小代码：

1. Workflow 静态契约测试：随机延迟步骤仅在 `schedule` 事件执行。
2. Pipeline 传递测试：已取得的行情对象以关键字参数传入基本面聚合。
3. 基本面成功复用测试：传入行情时估值字段正确，且不调用 `get_realtime_quote()`。
4. 首次失败重试测试：传入 `None` 时仍调用现有实时行情入口。
5. 现有实时行情、基本面、Pipeline 定向测试与 `scripts/ci_gate.sh` 通过。

## Action 验收

提交并推送分支后，使用当前四股池 `000777,002077,002270,002793` 手动触发 `stocks-only`、`force_run=true`：

- 随机延迟步骤状态为 `skipped`。
- 四只股票分析成功率与产物正常。
- 每只成功取得实时行情的 A 股只出现一次腾讯实时接口调用，基本面日志显示复用。
- 记录核心分析耗时、Workflow 总耗时、限流、超时和 fallback 情况。
- 盘后运行仅作为观察与性能证据，不作为同日交易指令。

预计减少 20～40 秒是基于既有日志的工程估计，不作为验收硬指标；最终以新 Action 日志和耗时为准。

## 风险与回滚

- 风险：同一次分析内估值读取的是数秒前的行情快照。该快照本来已用于技术面和报告，复用反而能保证同一报告内部价格口径一致。
- 回滚：删除 Workflow 的事件条件、Pipeline 的关键字传参及 Manager 的可选参数分支，即可恢复原行为，不涉及数据迁移。
